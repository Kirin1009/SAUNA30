# ととのい帳 v2.0 実装設計

Issue #26 の初期実装設計。承認済みビジュアルターゲットから、必要素材、データ統合、移行、画面実装の順に逆算する。

## 1. 素材リスト分解

### 紙と帳の基本素材

| 素材 | 用途 | 形式 | 備考 |
|---|---|---|---|
| 紙テクスチャ | 全画面背景、帳ページ、施設カード | CSS + 必要ならWebP | 既存の `#FEF6E6` / `#FFFFF8` を土台に、画像を使う場合は軽量WebP |
| 綴じ表現 | 帳画面の左端、ページ境界 | CSS優先 | 1ファイル主義に合わせ、影・線・小口で表現 |
| 通常栞 | 達成リワードの常設表示 | CSSまたはWebP | 金1種。県制覇、地方制覇、特性満願などに流用 |
| ごほうび栞 | 特別達成時の祝福 | WebP候補 | 全国制覇、常連10回、年間節目など |
| ページ影 | 帳をめくる質感 | CSS | パフォーマンス優先。390pxで重くしない |

### 判子文法 facSeal v2

既存のサ道場 `facSeal()` を母体に、全国施設と旧470枠へ広げる。

| 要素 | v1 | v2方針 |
|---|---|---|
| 形 | 施設タイプで丸/角/六角/五角 | 全国でも維持。未知タイプは丸 |
| 中央 | 施設名頭文字 | 長音・記号・括弧を除いた先頭有効文字 |
| 肩 | 市町村 | 全国470の `city` と東海149の市町村を統一 |
| モチーフ | 炎/双炎/雪/月/鍵/小判 | 既存に加えて桶、宿、外気、名湯を追加候補 |
| 常連金判 | なし | 同一施設10回以上は金判。施設判子に小さく「常」を重ねる |
| かすれ | `#sealtex` 共有 | 継続。大量表示時もフィルタ1個 |

## 2. データ設計

新ストアは `totonoi:v1`。移行元の生データを失わず、訪問 `visits` を核に据える。

```js
{
  v: 1,
  migratedAt: "2026-08-13T00:00:00.000Z",
  sources: {
    sauna30: { imported: true, version: "sauna30:v2" },
    sadojo: { imported: true, version: "sadojo:v1" }
  },
  settings: {
    bath: "m",
    radius: 300,
    userName: "Shun"
  },
  visits: [
    {
      id: "v<timestamp>-<hash>",
      facilityId: "sid:<sauna-ikitai-id>",
      sourceFacilityIds: ["sauna30:g1", "sadojo:t1234"],
      sourceVisitIds: ["sauna30:<old-id>"],
      visitedAt: "2026-08-13",
      method: "gps",
      score: { v: 2, axes: [4.2, 4.0, 4.4, 4.1, 3.8], extra: 0, why: "" },
      paid: 980,
      stars: 4.5,
      memo: "",
      photoIds: [],
      tags: []
    }
  ],
  wants: ["sid:<sauna-ikitai-id>"],
  facilities: {},
  rewards: {},
  legacy: {}
}
```

### 施設ID

- 基本IDは `sid:<サウナイキタイID>`。`sid` がない施設は `coord:<lat-lng-rounded>` または `user:<timestamp>`
- `sauna30` の枠ID、サ道場の `t<id>`、自分で登録した `u<ts>` は `sourceFacilityIds` に残す
- 重複解決は座標250mルールを第一優先、次に `sid`、最後に名前正規化

### 採点

- 保存はサ道場スタイルの5点満点5軸 + 特別加減点で統一し、表示で100点換算する
- `sauna30:v2` の4軸25点 + 特別±10は、既存のサ道場v2.8換算式を流用する
  - 各軸: `oldAxis / 5`
  - 特別: `oldExtra / 4`
  - 導線: `2.5`
  - `v:2` を付与
- 旧採点の元値は `legacy` に保持し、将来の検証で見返せるようにする

### 写真

- IndexedDB `sauna30/photos` の画像は削除しない
- `totonoi` 側の visit は旧 photo id を参照し、必要になった段階で `totonoi/photos` へコピーする
- バックアップJSON読み込み時は写真込み形式を維持する

## 3. 移行パス

1. `totonoi:v1` がなければ移行ウィザードを表示
2. localStorage `sauna30:v2` を読み、訪問、行きたい、タグ、自由登録施設、浴室設定を取り込む
3. IndexedDB `sauna30/photos` は参照を温存する
4. localStorage `sadojo:v1` を読み、東海149の押印、行きたい、自由登録、採点、支払を取り込む
5. 250m以内の施設を同一施設候補として統合する
6. 重複訪問は日付 + 施設 + source を見て1件化する。ただし同日複数回訪問の可能性があるため自動削除はしない
7. 移行結果を確認画面に出し、書き込み前に件数を表示する
8. 移行後も旧キーは消さない

## 4. 画面実装順

1. `totonoi:v1` の読み書きと移行ウィザード
2. 帳ホーム: 既存の記録ファーストUIを新ストアに接続
3. 施設ページ: 施設判子、訪問履歴、採点、写真、支払
4. 探す: 全国 + 東海の統合施設リスト、特性フィルタ、距離順
5. 棚: 既存の県鳥パズル、サ道場お題、栞を統合
6. 既存2アプリへの誘導バナーとバックアップ経由取り込み

## 5. リリース設計

- v2.0 は `APP_VERSION` をメジャー更新する
- `sw.js` は現行通り `APP_VERSION` クエリでキャッシュ名を変える
- 既存URLは残す。リリース後、Sauna470s とサ道場に「ととのい帳へ」バナーを出し、更新停止を明示する
- main 直デプロイ前に390pxで帳、探す、施設ページ、棚、設定を確認する
- 移行前後で以下を検証する
  - 訪問件数が減らない
  - 写真参照が切れない
  - 旧470枠の押印が消えない
  - サ道場の採点、支払、行きたいが残る
  - 既存キーを削除しない
